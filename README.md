# Visual Knowledge Integration（视觉认知库）

一个装进 AI 的完整视觉认知库：**构图结构、光影、色彩、镜头视点、视觉心理、质感风格、诊断评审** 八个知识域，配三层模式体系（体验 × 功能 × 流派）。

让任何需要画面思考的场景——想画什么、怎么排、哪里不对、多图怎么变——都有可推理的知识与可执行的思路。

## 三条铁律

1. **只给视觉认知与画面思路，不代写任何提示词。** 不生成、不改写、不评价提示词文本。其他流程写提示词时，本库的角色是提供画面决策输入：构图怎么定、光怎么配、色怎么用、风险在哪。
2. **完全模型无关。** 库内知识不绑定任何生图模型、平台参数、权重语法。
3. **知识完整优先。** 量化判据、数值带宽、反例、边界条件全部保留，不为省篇幅裁剪知识。

## 何时使用

- 要画一张图（不管最后用什么工具），需要构思画面。
- 觉得画面"太平／乱／没焦点／AI 味重"，需要诊断修复。
- 多图／组图场景需要编排变化、防止重样。
- 想学视觉概念（视觉重量、图底关系、动态对称……）。
- 多个画面方案之间要做选择评审。

## 何时不用

- 代写提示词（任何格式）——本库只在画面认知层给输入。
- 生成／编辑图片本身——不调用绘图工具，不产出图像文件。
- 纯文案排版校对、视频运镜的连续时间轴设计。

## 使用方式

本库是一个 **Agent Skill**：`SKILL.md` 带 `name` / `description` 元数据，是唯一入口。把整个目录放进所用 AI 客户端的 skills 目录即可（例：`<skills-root>/visual-knowledge-integration/`），AI 在讨论构图、用光、配色、风格、诊断等任务时会自动命中，并按 `SKILL.md` 的路由规则读取 `modes/` 与 `references/` 下的文件。

单次任务通常只需读取少量文件：先按 `SKILL.md` 第一、二步定功能与体验档，再按需读对应流程文件与知识域文件；构思／评审类任务会额外做流派硬路由。

## 核心流程

1. **识别任务类型（五功能）** —— learn / ideate / diagnose / compare / sequence，按意图路由后声明所用功能。
2. **确认体验档** —— 专家 / 经理（默认）/ 甲方 / 野狗，仅限用户点名切换。
3. **流派硬路由（构思、评审类强制）** —— 先走 `modes/schools/_index.md` 决策树定主派，再读主派文件的"核心思维方式 + 技法库 + 量化判据"，方案里显式引用该派技法或判据。

## 说明

- 知识库自成体系，无外部来源标注，内容以中文撰写。
- 库内所有判据均面向画面认知，不涉及任何具体生图模型的参数与语法。
